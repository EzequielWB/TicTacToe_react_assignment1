1. QUE ES REACT (Y QUE NO ES)
-----------------------------

React es una libreria para construir interfaces. La idea central es una sola
frase:

    la interfaz = f(estado)

Vos describis como se ve la pantalla para cada estado posible. Cuando el estado
cambia, React vuelve a ejecutar tus funciones y actualiza el DOM (los elementos
de la pagina) por vos. Nunca llamas a document.getElementById para cambiar un
texto o agregar un boton: cambiás el estado y la pantalla se ajusta sola.

Esto se llama declarativo. La alternativa, imperativa, seria decir paso a paso
"busca este elemento, sacale la clase, ponéle este texto, agregá un hijo".
React hace esa parte.

Tres palabras que vas a ver mucho:

- componente: una funcion de JavaScript que devuelve JSX.
- JSX: una sintaxis que parece HTML pero es JavaScript. <Player /> es, por
  debajo, una llamada a la funcion Player con un objeto de argumentos.
- render: el momento en que React ejecuta tus componentes y calcula el JSX
  resultante. No es lo mismo que "pintar en pantalla": React calcula el arbol
  nuevo, lo compara con el anterior y aplica solo lo que cambio. A eso se le
  dice reconciliacion.

React no es un framework completo. No trae enrutamiento, ni base de datos, ni
llamadas HTTP incluidas para este caso. Aca solo se usa la parte de interfaz.
Vite es la herramienta que levanta el servidor de desarrollo y empaqueta el
codigo para produccion.


2. MAPA DE ARCHIVOS
-------------------

index.html
    El cascara HTML. Trae el logo, el <h1>TaTeTi</h1> y un <div id="root"></div>.
    Ese div esta vacio: React lo rellena. Ojo: el header NO es React, es HTML
    comun. El script apunta a /src/index.jsx.

src/index.jsx
    El punto de entrada. Crea la raiz de React sobre #root y renderiza <App />.
    Son tres lineas. Aca no hay estado ni reglas del juego.

src/App.jsx
    El componente principal y el dueno de todo el estado. Aca estan las reglas:
    quien juega, como se arma el tablero, quien gano y como se cuenta el score.

src/components/Player.jsx
    Un jugador: nombre editable, avatar, tooltip con estadisticas y el boton
    Edit/Save. Se usa dos veces, una por jugador.

src/components/GameBoard.jsx
    El tablero 3x3. Recibe el tablero ya calculado y solo lo dibuja. No sabe
    quien gano ni como se calcula un turno.

src/components/GameOver.jsx
    El cartel que tapa el tablero cuando termina la partida. Recibe el nombre
    del ganador (o nada, si fue empate) y el boton Rematch.

src/components/Log.jsx
    La lista de jugadas a la derecha, con el ultimo turno resaltado.

src/winning-combinations.js
    Las 8 ternas de casillas que ganan: 3 filas, 3 columnas y 2 diagonales.
    Cada casilla es { row, column }.

src/scores.js
    La funcion pura addResult(scores, winner). Suma una victoria al ganador o
    un empate a los dos. No muta nada, devuelve un objeto nuevo.

src/scores.test.js
    Dos pruebas con node:test: una para victoria, una para empate.

src/index.css
    Todos los estilos de la aplicacion. No hay CSS por componente.

public/
    Archivos estaticos. Vite los copia tal cual a la raiz del build. Por eso
    /avatar-default.jpg funciona: el archivo esta en public/avatar-default.jpg.

dist/
    El resultado de npm run build. Es lo que se sube a Vercel. No se edita.

avatar/
    Material de la catedra, no se importa desde ningun lado del proyecto.
    Ojo: los nombres estan mezclados. messi.jpg es CSS, missing-in-action.jpg
    es un componente, y los JPEGs reales se llaman package.json y
    package-lock.json. No lo borres sin guardar una copia si queres usarlo en
    la clase de dudas.


3. QUE PASA DESDE QUE ABRIS LA PAGINA HASTA QUE VES EL TABLERO
-------------------------------------------------------------

1) El navegador descarga index.html y ve el script /src/index.jsx.
2) Vite (en desarrollo) o el bundle (en produccion) entrega ese modulo.
3) index.jsx ejecuta:

       ReactDOM.createRoot(document.getElementById('root')).render(<App />);

4) React llama a la funcion App. App usa hooks, calcula valores y devuelve JSX
   con <Player />, <GameOver /> (si corresponde), <GameBoard /> y <Log />.
5) React llama a cada componente hijo con sus props y arma el arbol de elementos.
6) React compara con el arbol anterior (la primera vez no hay nada) y escribe
   los nodos reales en #root.

Despues, cada vez que cambia un estado con setAlgo(...), React vuelve al paso 4.
Los hijos vuelven a renderizarse con las props nuevas. Ese ciclo es el corazon
del framework.


4. EL ESTADO: LOS CUATRO DATOS QUE MANEJA LA APLICACION
-------------------------------------------------------

Dentro de App hay tres useState y un useRef:

    const [players, setPlayers] = useState(PLAYERS);
    const [scores, setScores] = useState(INITIAL_SCORES);
    const [gameTurns, setGameTurns] = useState([]);
    const countedTurns = useRef(null);

players
    { X: 'Player 1', O: 'Player 2' }. Los nombres. Se actualizan cuando apretas
    Save en un Player, mediante handlePlayerNameChange(symbol, newName).
    Se necesitan en App para mostrar "X won!" en GameOver con el nombre real.

scores
    { X: { wins: 0, draws: 0 }, O: { wins: 0, draws: 0 } }. Lo que muestra el
    tooltip de cada avatar.

gameTurns
    La fuente unica de verdad del juego. Un array de turnos, el mas reciente
    primero:

        [
          { square: { row: 1, col: 1 }, player: 'X' },
          { square: { row: 0, col: 0 }, player: 'O' }
        ]

    Aca NO se guarda el tablero. El tablero se calcula a partir de estos datos.
    Guardar una sola fuente evita que el tablero y la lista de jugadas se
    contradigan.

countedTurns
    Un useRef. Es una "caja" con un valor que se conserva entre renders pero
    que NO dispara un render cuando cambia. Se usa para acordarse de que ya
    contamos el resultado de este array de turnos. Mas en la seccion 8.

Por que no alcanza con una variable comun? Porque App se ejecuta de nuevo en
cada render. Una variable normal se reinicia y React no sabe que tiene que
actualizar la pantalla. Los hooks useState/useRef le dicen a React: "guardame
esto entre renders".

Actualizacion con funcion
    handleSelectSquare usa:

        setGameTurns((prevTurns) => { ... return updatedTurns; });

    En vez de usar gameTurns directamente. La funcion recibe el valor mas
    reciente, aunque React haya agrupado varios cambios en el mismo tick. Es
    la forma correcta cuando el nuevo valor depende del anterior.

Reinicio
    handleRestart solo hace setGameTurns([]). El tablero se vacia, pero scores
    se queda: las estadisticas son acumuladas entre partidas.

Nombre editable
    Player tiene su propio useState(playerName) mientras escribis. Recien
    cuando apretas Save llama a onChangeName(symbol, playerName), que sube el
    dato hasta App. A esto se le dice "elevar el estado": el dato vive en el
    componente comun mas cercano porque mas de uno lo necesita.


5. LOS VALORES DERIVADOS: LA PANTALLA ES UNA FUNCION DEL ESTADO
---------------------------------------------------------------

App calcula cuatro cosas antes de devolver JSX:

    const activePlayer = deriveActivePlayer(gameTurns);
    const gameBoard    = deriveGameBoard(gameTurns);
    const winner       = deriveWinner(gameBoard);
    const hasDraw      = gameTurns.length === 9 && !winner;

deriveActivePlayer(gameTurns)
    Empieza jugando X. Si el ultimo turno (gameTurns[0], porque el array esta
    ordenado de mas nuevo a mas viejo) fue de X, ahora juega O. En otro caso,
    juega X. Es una regla de 4 lineas.

deriveGameBoard(gameTurns)
    Parte de INITIAL_GAME_BOARD, un array 3x3 de null. Hace una copia de cada
    fila con map((array) => [...array]) y despues "reproduce" los turnos:

        gameBoard[row][col] = player;

    La copia importa: si escribieras directo sobre INITIAL_GAME_BOARD, el
    tablero inicial se iria modificando y la proxima partida arrancaria sucia.
    El tablero es un dato calculado, no un estado guardado.

deriveWinner(gameBoard)
    Recorre las 8 combinaciones de winning-combinations.js. Si las tres
    casillas tienen valor y son iguales, devuelve el simbolo ('X' u 'O').
    Si ninguna combinacion cumple, devuelve undefined. App traduce ese
    simbolo a nombre recien en el JSX: winner && players[winner].

hasDraw
    Nueve turnos ocupados y sin ganador. Es un empate.

Por que calcular en vez de guardar? Porque asi nunca puede pasar que el
tablero diga una cosa y el log otra. Todo sale del mismo array de turnos.
El costo es que se recalcula en cada render, pero con 9 casillas es gratis.


6. COMPONENTES Y PROPS: COMO SE PASA LA INFORMACION
---------------------------------------------------

Un componente es una funcion que recibe props (un objeto con argumentos) y
devuelve JSX. El flujo es de una sola via: los datos bajan por props y los
eventos suben por callbacks.

    App (tiene el estado)
      |  props: board, stats, isActive, turns, winner
      v
    Componentes hijos
      |  eventos: onSelectSquare, onChangeName, onRestart
      v
    App (llama a un setState) -> nuevo render

GameBoard recibe:
    board          el tablero 3x3 ya calculado.
    onSelectSquare una funcion de App. El tablero no la inventa, solo la llama
                   con (rowIndex, colIndex) cuando apretas una casilla.

Player recibe:
    initialName    el nombre inicial.
    symbol         'X' u 'O'.
    isActive       si es el turno de este jugador.
    onChangeName   callback para avisar a App que el nombre cambio.
    stats          { wins, draws } para el tooltip.

GameOver recibe:
    winner         el nombre del ganador, o undefined si fue empate.
    onRestart      callback que limpia los turnos.

Log recibe:
    turns          el array de jugadas para mostrar la historia.

Ningun hijo modifica las props. Si Player necesita cambiar el nombre, no hace
players.X = 'otro'; llama a onChangeName y App decide como actualizar su estado.


7. EVENTOS: COMO REACT SE ENTERA DE LO QUE HACES
------------------------------------------------

Casilla del tablero
    GameBoard dibuja un <button onClick={() => onSelectSquare(rowIndex, colIndex)}>.
    La funcion flecha "captura" rowIndex y colIndex: cuando apretes, esos
    valores siguen disponibles. El boton ademas tiene disabled={playerSymbol !== null},
    asi que una casilla ocupada no se puede apretar.

Nombre
    El <input type="text" value={playerName} onChange={handleChange}> es un
    input controlado. El valor que ves en pantalla viene del estado, y cada tecla
    actualiza el estado. React es el dueno del valor, no el DOM.

Avatar
    Tenemos un <label> que envuelve la imagen y un input de archivo oculto:

        <label className="player-avatar">
          <img ... />
          <input type="file" accept="image/*" hidden onChange={handleAvatarChange} />
        </label>

    Al clickear la imagen, el label transmite el click al input y se abre el
    selector de archivos. No hace falta document.getElementById ni un id
    unico, y por eso los dos jugadores pueden tener su propio input sin
    pisarse. handleAvatarChange lee event.target.files[0] y crea una URL
    temporal con URL.createObjectURL(file). Esa URL va al estado avatar y el
    <img> la muestra. Es mas corto que FileReader y no necesita un callback
    onload.

Tooltip
    Es el atributo title del <img>:

        title={'Wins: ' + stats.wins + ' · Draws: ' + stats.draws}

    El navegador muestra ese texto al pasar el mouse, sin CSS ni JavaScript
    extra. Es una limitacion: no se puede estilizar y tarda un momento en
    aparecer, pero cumple lo que pide el enunciado.

Boton Rematch
    Llama a onRestart, que llega a App y ejecuta setGameTurns([]).


8. EL EFECTO QUE CUENTA VICTORIAS Y EMPATES
-------------------------------------------

Codigo en App:

    useEffect(() => {
      if ((!winner && !hasDraw) || countedTurns.current === gameTurns) return;
      countedTurns.current = gameTurns;
      setScores((prev) => addResult(prev, winner));
    }, [winner, hasDraw, gameTurns]);

useEffect sirve para reaccionar despues de un render. El arreglo de
dependencias le dice a React: "volvé a ejecutar esto cuando cambie winner,
hasDraw o gameTurns".

La primera linea es un guard. sale sin hacer nada en dos casos:

- todavia no hay ganador ni empate (la partida sigue);
- este mismo array gameTurns ya fue contado (countedTurns.current === gameTurns).

El guard existe porque un efecto puede ejecutarse mas de una vez para el
mismo render. En este proyecto no esta activado React.StrictMode en
src/index.jsx, pero si alguien lo agregara, React ejecutaria los efectos dos
veces en desarrollo y el score se contaria doble. Comparar la identidad del
array (===) es barato y evita el problema. Cuando apretas Rematch se crea un
array nuevo, asi que la proxima partida se cuenta normal.

addResult(scores, winner) es una funcion pura, en src/scores.js:

- si recibe 'X' o 'O', suma 1 a wins de ese simbolo;
- si recibe undefined (empate), suma 1 a draws de los dos;
- siempre devuelve objetos nuevos, nunca modifica el anterior.

Por eso fue facil probarla: src/scores.test.js usa node:test y comprueba los
dos casos. Es la unica logica nueva con test automatico.

Por que no contar adentro de handleSelectSquare? Porque ahi habria que
recalcular tablero y ganador, duplicando lo que ya hacen las funciones
derive*. Por que no contar en handleRestart? Porque el tooltip quedaria
desactualizado hasta que apretes Rematch: ganas, pasas el mouse por el avatar
y todavia mostraria el score viejo. El efecto se dispara apenas termina la
partida.


9. AVATAR Y TOOLTIP: LO QUE AGREGAMOS PARA LA ENTREGA
-----------------------------------------------------

Decisiones y razones:

- Avatar inicial: public/avatar-default.jpg. Es una copia del JPEG de 500x500
  que en la carpeta avatar/ se llama package.json. Vite copia public/ al
  build, y por eso la ruta absoluta /avatar-default.jpg funciona en Vercel.

- Estado del avatar: local de Player, al lado de playerName. Se mantiene
  aunque apretes Rematch porque los componentes Player no se desmontan, solo
  reciben props nuevas.

- Score: en App, porque es un dato comun a los dos jugadores y ademas lo
  actualiza el efecto. Player solo lo recibe para mostrarlo en el title.

- Imagen clickeable: un <label> con el input oculto adentro. Sin IDs globales
  ni codigo que busque elementos en el DOM.

- Tooltip: atributo title nativo. Cero codigo extra.


10. UN TURNO COMPLETO, PASO A PASO
----------------------------------

Supongamos que X aprieta la casilla fila 1, columna 1.

 1) El onClick de GameBoard llama a onSelectSquare(1, 1).
 2) handleSelectSquare, dentro de setGameTurns, calcula el jugador actual con
    deriveActivePlayer(prevTurns) y arma updatedTurns con el turno nuevo al
    principio.
 3) React guarda el array nuevo y vuelve a renderizar App.
 4) deriveGameBoard reproduce todos los turnos: la casilla (1,1) ahora vale X.
 5) deriveWinner revisa las 8 combinaciones. Si no hay tres X alineados,
    winner es undefined.
 6) GameBoard recibe el tablero nuevo. El boton (1,1) muestra X y queda
    disabled. El jugador activo pasa a ser O, asi que el borde amarillo se
    mueve al otro Player.
 7) Log muestra la jugada nueva arriba.
 8) Si era la jugada final, el useEffect ve winner (o hasDraw) y actualiza
    scores. Los tooltips pasan a mostrar, por ejemplo, "Wins: 1 · Draws: 0".
 9) Si hay ganador o empate, aparece GameOver. Rematch llama a setGameTurns([])
    y todo vuelve al tablero vacio, con los scores acumulados.


11. CSS: COMO SE CONECTA CON LOS COMPONENTES
--------------------------------------------

Los selectores principales de src/index.css:

    #players        la fila con los dos jugadores.
    #players li.active
                    el borde amarillo y la animacion del jugador en turno.
                    Se activa porque Player pone className="active" cuando
                    isActive es true.
    .player         contenedor del avatar, nombre y simbolo. Es inline-flex
                    para que queden en la misma fila.
    .player-avatar  el <label>. Le da cursor: pointer.
    .player-avatar img
                    imagen circular de 3.5rem con object-fit: cover.
    .player-name    el nombre, con ancho fijo y texto en mayusculas.
    .player input   el campo de texto cuando estás editando el nombre.
    #game-board     grilla de botones de 8rem.
    #game-over      capa absoluta que tapa el tablero al terminar.
    #log            lista de jugadas a la derecha.

El truco de className={isActive ? 'active' : undefined} es comun en React:
cuando la condicion es falsa, no se agrega ninguna clase. El CSS solo reacciona
a la clase que si existe.


12. COMANDOS Y DEPLOY
---------------------

Abrir una terminal en la raiz de la carpeta:

    npm install       instala las dependencias (una sola vez).
    npm run dev       levanta Vite en http://localhost:5173.
    npm test          corre las dos pruebas de scores.js.
    npm run build     genera dist/ para produccion.
    npm run preview   sirve dist/ localmente para probar el build.

Para Vercel:
    - importar el proyecto desde el repositorio Git;
    - framework preset: Vite;
    - build command: npm run build;
    - output directory: dist.

Esta carpeta, al momento de escribir esta guia, no es un repositorio Git. Si
el deploy se hace desde Git, primero hay que hacer git init, agregar un remoto
y subir el codigo.


13. PROBLEMAS PREEXISTENTES Y LIMITACIONES
------------------------------------------

- npm run lint no funciona. No hay archivo de configuracion de ESLint en el
  proyecto y, ademas, avatar/package.json es un JPEG, asi que ESLint intenta
  leerlo como JSON y falla. Borrar avatar/ saca el segundo error pero no el
  primero. Arreglarlo requiere crear una configuracion de ESLint.

- npm run build pasa, pero avisa que bg-pattern-dark.png no se resolvio en
  build time. El archivo esta en public/, asi que el warn es viejo y no viene
  de los cambios de avatar.

- El marcador y los avatares viven solo en memoria. Si recargas la pagina,
  vuelven al valor inicial (0 victorias y la imagen por defecto). Para persistirlos
  habria que usar localStorage o un backend.

- Solo hay tests automaticos para addResult. No hay tests de clicks ni de
  renderizado, porque no hay una libreria de testing instalada. La verificacion
  del resto fue build + revision manual del codigo.

- La carpeta avatar/ tiene los archivos con nombres incorrectos. Es material
  de la catedra, no codigo que se ejecute.


14. EJERCICIOS PARA APRENDER DE VERDAD
--------------------------------------

Elegí uno y hacelo sin mirar la solucion (no hay solucion aca, a proposito).

1) Cambiar el texto del tooltip a algo como "Ganados: 2 | Empatados: 1".
   Pista: una sola linea en Player.jsx.

2) Agregar derrotas al marcador. Pista: fijate como addResult decide ganador
   o empate, y como se pasa stats desde App.

3) Hacer que los avatares sobrevivan a una recarga. Pista: localStorage en el
   inicializador de useState y un useEffect que guarde cuando cambie.

4) Agregar un boton "Reset score" en App. Pista: una funcion que llame a
   setScores(INITIAL_SCORES) y un <button> en el JSX.

5) Reemplazar el title por un tooltip estilizado con CSS. Pista: un contenedor
   con position: relative y un hijo con position: absolute que aparezca en
   :hover. Esto rompe la regla de "tooltip nativo", pero es un buen ejercicio.

6) Mostrar "It's a draw!" con el contador de empates de cada jugador.
   Pista: GameOver recibe props, pasale lo que necesite.

7) Probar deriveWinner y deriveGameBoard con node:test. Pista: exportalas desde
   un modulo .js (no .jsx) para poder importarlas desde Node.

8) Explicar con tus palabras por que deriveGameBoard copia cada fila. Si
   puedes explicarlo sin mirar el codigo, entendiste el punto mas importante
   del archivo App.jsx.

9) Borrar avatar/ despues de guardar el material en otro lado, y correr build
   de nuevo para comprobar que nada se rompe.


15. GLOSARIO
------------

componente      funcion que devuelve JSX y describe una parte de la interfaz.
JSX             sintaxis parecida a HTML que se transforma en llamadas a React.
estado          dato que React conserva entre renders y que dispara renders.
props           datos que un componente padre le pasa a uno hijo.
render          ejecucion de los componentes para calcular el arbol de JSX.
hook            funcion especial de React (useState, useEffect, useRef).
useState        guarda un valor y devuelve [valor, funcionParaCambiarlo].
useRef          guarda un valor entre renders sin disparar un render.
useEffect       corre codigo despues del render cuando cambian sus dependencias.
derivado        valor que se calcula a partir del estado en vez de guardarse.
callback        funcion que se pasa como prop para que el hijo avise al padre.
key             identificador que React usa para reconocer elementos de listas.
controlado      input cuyo valor viene del estado, no del DOM.
puro            funcion que siempre devuelve lo mismo para los mismos datos y
                no modifica nada fuera de ella.
reconciliacion  comparacion entre el arbol nuevo y el anterior para cambiar
                solo lo necesario en el DOM.
bundler         herramienta que junta modulos y genera archivos para el
                navegador. Aca es Vite.
